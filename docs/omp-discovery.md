# External OMP conversations

PinkCollab can inspect an existing host conversation before owning a runtime. Tasks shows it as **History**. Open it to read saved messages; send a message or use the existing start action to continue it. Close the external OMP instance first. No manual import is required.

## Storage evidence and adapter

Implementation was checked against the installed `omp/18.4.2` package, specifically `session/session-entries.ts`, `session/session-listing.ts`, `session/session-index.ts`, `session/session-storage.ts`, `session/session-manager.ts`, `modes/rpc/rpc-types.ts`, and `pi-utils/src/dirs.ts`.

OMP exposes `SessionManager.list/listAll` in its JavaScript SDK, but no listing command in its RPC/CLI. Its SDK enumerates `*/*.jsonl` and reads file windows; local listing can also recover backup files and inspect whole transcripts. `history.db`'s `session_titles` index only maps IDs to titles, not paths/cwd, so it cannot enumerate authoritative history sources. The Gateway uses a small read-only Rust adapter rather than embedding Bun/the SDK or performing its repair writes. It understands version-3 session headers and the fixed first-line `title` slot; other versions are excluded. Android never parses OMP records.

## Scope and refresh

The adapter follows absolute `--session-dir` from `omp_args` (flat directory), otherwise the active profile selected by `--profile`, `OMP_PROFILE`, then the legacy `PI_PROFILE` fallback. An explicitly empty `OMP_PROFILE` selects the default profile. Profile names follow OMP normalization, including names such as `work.dev`. The default root is `~/.omp/agent/sessions`; relative `PI_CONFIG_DIR` overrides the `.omp` config directory name. `PI_CODING_AGENT_DIR` is supported for the default profile. On Linux/macOS an existing `$XDG_DATA_HOME/omp[/profiles/<profile>]` takes precedence when no agent override is present. Use an absolute `--session-dir` for custom storage layouts or wrappers. Only the Gateway service account's selected storage is visible; other accounts/profiles are not scanned.

Each on-demand refresh visits at most 8,192 directory entries, at depth one below the standard sessions root (no descent for an explicit session directory). It considers the newest 1,024 JSONL files among those visited and reads at most 16 KiB per file. Entries beyond these budgets may be omitted. It never follows discovered directory/file links, scans project contents, reads full transcripts for listing, writes OMP indexes, or repairs files. A single bad file is isolated. Metadata is cached for 15 seconds; the next list/snapshot request after expiry refreshes it. There is no polling daemon or unsolicited external-change WebSocket stream. Reopen/reconnect the app to obtain a fresh snapshot. A deleted source is filtered immediately from cached lists. REST list pages retain database keyset pagination, merge at most one managed page with the bounded discovery cache, and only capture runtime summaries for the returned page. Indexed reference ownership suppresses managed copies without reopening every managed history file.

All cwd values (and any OMP additional workspace directories) must be absolute, exist, and pass Gateway's canonical workspace allowlist. Missing/deleted projects, relative or malformed cwd, and links escaping the allowlist are excluded. Moving a project does not authorize following OMP relocation hints. Workspace changes take effect when Gateway reloads its configuration, as for managed sessions.

## Identity, history and adoption

The opaque public ID hashes the OMP header ID and remains the same on refresh, restart and adoption. Multiple visible files with the same OMP ID are ambiguous and omitted. Managed IDs and canonical mapped references suppress discovered copies. Existing managed sessions retain their IDs.

Discovery never inserts a `session_records` row. A discovered snapshot has `origin: discovered`, `runtime: null`, empty live timeline/operations, and `hasHistory: true`. Creation time comes from the OMP header; update time is file modification time, not evidence of execution or completion. Title preference is the current title slot, header title, first user text in the bounded prefix, then `OMP conversation`. No title-generation model or transcript metadata write is used.

History uses the existing strict branch reconstruction, limits and source-bound cursor pipeline. A transcript path is never public. Identity is rechecked before discovered reads and before every adopted history read/runtime start. Corrupt/replaced history produces `history_unavailable`; disappearance can produce `session_not_found`. Neither creates an empty replacement.

A generation-less prompt or `start_runtime` revalidates workspace, source identity, observed write activity, and strict history, then commits a normal SessionRecord and its OMP mapping together with an `omp_adoptions` row. SQLite schema 5 keeps `omp_adoptions(omp_id PRIMARY KEY, session_id UNIQUE, reference UNIQUE)` and adds `engine_references(reference_key PRIMARY KEY, session_id)` for indexed ownership across all managed sessions. Reference normalization happens before acquiring the database lock; the row and unique reference claim commit atomically. Migration reserves existing references without deleting legacy duplicate session records. Adopted history is marked possibly written immediately. The same public ID becomes managed, so outbox keys, history cursors and pager selection remain stable. Both tables contain metadata only.

`BEGIN IMMEDIATE`, unique constraints and deterministic identity make concurrent adoption retries converge on one row, including separate database connections. Adoption commits before ordinary command admission; a crash between these steps leaves a managed historical session with no runtime. The ordinary durable receipt then owns dispatch. Existing generation guards, unknown outcomes, runtime leases and stop behavior are unchanged. After `switch_session`, startup also checks the runtime’s actual `sessionId` against the persisted OMP ID before dispatching a prompt, so a file replaced during startup cannot redirect the conversation. An identical command ID dispatches once; distinct simultaneous commands still obey existing generation rules. Adoption failure before receipt creation has no execution side effect.

## External writers and limitations

OMP 18.4.2 serializes individual file publishes using a sibling `.<filename>.lock` and OS gate, and protects full rewrites with expected-size checks. These are **not a lifetime runtime ownership lock**. PinkCollab refuses a present publish lock or a file changing during a 200 ms quiet check, returning `external_session_busy`. It does not delete stale OMP locks. A strict read also rejects concurrent changes.

These checks cannot prove an idle external OMP process is absent or prevent it waking later. Concurrent interactive use of the same history is unsupported: close it on the host before continuing from the phone, and do not reopen it elsewhere while PinkCollab owns its runtime. PinkCollab does not claim safe external process takeover or cross-application exclusive leases. Older/future OMP writer behavior and custom non-file storage have not been validated.

## Validation

`gateway/tests/discovery.rs` covers read-before-adopt REST history and pagination, a racing first prompt, original history continuity, stable identity, canonical allowlists, malformed/deleted sources, duplicate mappings, concurrent transactions, workspace removal, writer locks, persisted adoption mappings, mixed pagination across adoption, and identity replacement during startup. Storage tests cover migration, mapping rollback and competing claims from separate connections. Layout tests cover profile/environment precedence and XDG selection. Adapter tests exercise cache expiry and changing-file rejection. The subprocess fixture switches to the requested source rather than faking a successful resume. An opt-in real OMP test resumes isolated version-3 history through the full discovery/adoption/start path without sending a model prompt; it also checks Windows path handling.

Android unit tests cover explicit origin parsing/reduction, History cards and work status, opening/retrying history, continuing without a runtime, draft retention on failure, and same-ID replacement without losing cached history. The existing device suites also compile against the additive field. Device execution still requires an attached emulator/phone.
