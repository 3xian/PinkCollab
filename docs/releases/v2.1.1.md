PinkCollab v2.1.1: early Android session loading and lifecycle-owned focus

## Highlights

- Begin loading the initial conversation during Android startup, using the pager's session ordering and the current restored selection when available.
- Request the latest 10 saved messages for initial conversation loading instead of 25; earlier messages remain available through pagination.

## Fixes

- Give Tasks one lifecycle-aware session-focus collector. Leaving Tasks or backgrounding the app cancels pending snapshot waits and page-focus debounces, preventing late startup snapshots from initiating focus on another route.
- Reuse pending detail requests and valid subscriptions when the pager opens; resolve the current selection on reentry and reload invalidated subscriptions after reconnects.
- Keep startup navigation's eight-second limit separate from host synchronization state. An in-progress connection remains loading, recovery returns unavailable hosts to loading, and previously synchronized session lists remain available across disconnects.
- Use standard gzip compression for negotiated compressed WebSocket frames.
- Improve OMP onboarding instructions and the website's provider-usage presentation, and update the MIT copyright attribution to Pink.

## Compatibility and upgrade

- Protocol 3 and database schema 5 are unchanged; no data migration is required. Older Gateways continue to use the existing text/REST fallback.
- Install the signed Android APK over the existing app to preserve phone-side pairings. Debug builds cannot upgrade production APKs because their signing certificates differ.
- Upgrade the Gateway with `npm install -g pinkcollab@2.1.1`, then run `pinkcollab setup` or `pinkcollab service install` to update an existing background service. Restarting a Gateway stops active OMP runtimes; stored sessions and pairings remain.
