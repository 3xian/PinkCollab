PinkCollab v2.0.1: keep OMP executable paths stable across package-manager upgrades

## Fixes

- Gateway init and setup now persist the absolute OMP executable entry without resolving symlinks to version-specific targets. Replacing the target during a package-manager upgrade no longer leaves newly configured Gateways pointing at the removed version.
- Explicit executable paths retain their symlinks and still fail when broken rather than falling back to another executable on PATH. Windows executable lookup continues to honor PATHEXT.

## Compatibility and upgrade

- Protocol 3, database schema 5, and Android functionality are unchanged. This release includes matching Android, Gateway, and npm package versions.
- Upgrade with `npm install -g pinkcollab@2.0.1`, then run `pinkcollab setup` or `pinkcollab service install` to update an existing background service. Restarting a Gateway stops active OMP runtimes; stored sessions and pairings remain.
- Existing configurations are not automatically migrated from version-specific OMP paths. If `config.yaml` already points into an old version directory, change its `omp` value to the stable executable entry, such as `/opt/homebrew/bin/omp`, before running setup or restarting the Gateway. Do not delete the data directory or reinitialize it.
