PinkCollab v2.1.0: in-app Android updates, provider quotas, and compressed session loading

## Highlights

- Download Android updates inside PinkCollab with progress, cancellation, retry, and package/version/signature validation before opening Android's installer.
- Open Usage from Models to view host-wide provider account quotas without starting a session runtime or losing pending model settings.
- Load the first 25 saved messages alongside session snapshots when available, with optional gzip WebSocket frames and REST fallback for unavailable, slow, or oversized history.
- Refresh the model picker with compact controls, full-width search, and a localized thinking-level thumb glow.

## Fixes

- Preserve displayed conversation content when navigating away from Tasks and while subscriptions refresh; keep drafts visible while details load.
- Bound the initial history request to fifteen seconds and display connection-stage feedback during longer waits.
- Mark persistently unreachable hosts offline while continuing periodic probes; manual refresh and foreground/network recovery bypass the backoff.
- Preserve independent host usage results when requests overlap, and prevent cancelled update progress from replacing a newer attempt or completed download.
- Read usage from the configured OMP profile and contain its subprocess tree through timeout, output-limit failure, and request cancellation.

## Compatibility and upgrade

- Protocol 3 and database schema 5 are unchanged; no data migration is required. Upgrade Android and Gateway together to enable inline history and compressed frames; older peers retain the text/REST flow.
- Provider quotas require an OMP version supporting `usage --json`; unavailable reports are not interpreted as zero usage.
- Install the signed Android APK over the existing app to preserve phone-side pairings. In-app installation requires Android's per-app installation permission and installer confirmation; debug builds cannot upgrade to production APKs because their signatures differ.
- Upgrade the Gateway with `npm install -g pinkcollab@2.1.0`, then run `pinkcollab setup` or `pinkcollab service install` to update an existing background service. Restarting a Gateway stops active OMP runtimes; stored sessions and pairings remain.
