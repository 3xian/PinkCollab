PinkCollab v3.0.2: a unified antique-dark Android interface and safer Windows runtime recovery

## Highlights

- Redesigned the entire Android interface around warm charcoal and brown panels, antique brass edges, parchment-colored text, recessed inputs and amber primary actions. Sessions, conversation/tool surfaces, TODO plans, workspaces, pairing, configuration menus and model/usage/update dialogs share the same component system.
- Session cards retain explicit status badges and selection semantics. TODO plans keep their pinned header, bounded scrolling and expand/collapse behavior; composer controls retain their labels, action gating and End confirmation.
- Narrow layouts and enlarged text retain responsive Model/Fast controls and font-scaled session/TODO headers. Decorative backgrounds and material grain are static, with no moving full-screen effects.

## Fixes

- Android keeps retained conversation and tool information separate from confirmed live work, and preserves loading/readiness and current-work presentation across startup and synchronization transitions.
- On Windows, OMP runtimes use named, generation-specific Job Objects. Gateway crashes reap owned process trees, and restart checks reject stale runtime leases instead of treating old process ownership as current execution.
- Retained conversations and phone-side pairings remain separate from runtime process lifetime.

## Compatibility and upgrade

- Protocol 4 is unchanged. Install the signed Android APK over the existing app to preserve phone-side pairings; do not uninstall the production app to switch signatures.
- Update the Gateway with `npm install -g pinkcollab@3.0.2`, then run `pinkcollab setup` or `pinkcollab service install` to update the stable background binary.
- The Gateway database migrates automatically to schema 6 to record Windows runtime Job ownership. Back up the Gateway data directory before upgrading. Earlier releases that only support schema 5 cannot open the migrated database; do not downgrade in place.
- Gateway upgrades and graceful stops end active OMP runtimes while preserving stored conversations and pairings. Windows login startup still requires `pinkcollab service start` to recover a crashed Gateway.
