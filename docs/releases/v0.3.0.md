PinkCollab v0.3.0 — sessions name themselves, and the phone view stays put

## Highlights

- A session is named after its latest prompt: once OMP accepts a prompt, the title becomes that message as one line, cut at 80 characters, and the session card shows it. New sessions start as "New session". Attachment-only prompts, prompts OMP rejects, and duplicate command replays leave the title unchanged.
- The Android session screen no longer empties out while it refreshes. The transcript you were reading and the composer stay in place across reconnects, unfocus, and failed loads, and a failed load offers Retry instead of an empty conversation.
- The model picker's Thinking control is a slider with a bolt thumb and one tick per supported level, below the model list. Until a level is chosen, and for models with a single level, the picker offers plain level buttons that include the first level, so "off" or "low" is a choice you can make on purpose.
- The website hero walks through a real session — prompt, reply, running tool call, and composer — and a new section shows the Models screen.

## Fixes

- A session with no live runtime is read from its persisted record, so the session list and the session it opens no longer disagree; only an active runtime overlays live state.
- A session whose OMP transcript has not been written yet waits for that turn to settle instead of reporting empty history, and an in-flight first page is never replaced by "no messages".
- Events for a session the app no longer subscribes to are ignored, and a reconnect, unfocus, or unsubscribe ends the previous subscription's work without clearing what is on screen.
- The session pager requests its settled page once after scrolling stops instead of on every page change during a swipe.
- Failed and unconfirmed operations show a plain message — "Your message could not be sent. Please try again." or "Could not confirm the result. Check the conversation before trying again." — instead of internal command and status names.
- The conversation's placeholder text follows the session state: "Starting the agent…", "The agent is working…", "Stopping the agent…", "The agent needs your input.", or "Send a message to start the conversation."
- The composer keyboard offset follows the input method during placement, so the composer's text field and buttons are not re-measured frame by frame.

## Upgrade

Install the 0.3.0 app and Gateway together. The database schema and the wire protocol are unchanged: no migration runs on startup, and existing pairings, sessions, and transcripts keep working. Sessions created before this release keep their current title until their next prompt replaces it.
