PinkCollab v3.0.0: resumable Android connections and one complete conversation timeline

## Highlights

- History and live updates now form one ordered conversation. Gateway-supplied identities merge saved replies with live messages while preserving stable UI keys.
- Android resumes host and session updates after short connection interruptions. When replay is unavailable, each scope recovers from a fresh snapshot.
- History synchronization sends new messages, changed tools and confirmations of cached text instead of retransmitting the entire loaded conversation. Loaded older pages remain available while the conversation stays on the same branch.
- Tool arguments and results load on expansion, with paged details and polling for expanded running tools. Timeline summaries carry compact tool information and share repeated Todo plans.
- Large session catalogs load in pages, keeping attached runtimes and the focused session in the initial list. Long replies retain their full text; transport pages select fewer whole messages when needed.

## Fixes

- Prevent older host replay events from replacing a newer session snapshot or clearing its live messages. List and detail updates use independent sequence checks.
- Fetch a new tool-detail version again when its first request was cancelled before completion.
- Keep Todo reference resolution within the timeline contract, without rewriting unrelated JSON fields.
- Allow Android's recovery action to restart hosts that are still connecting or synchronizing.

## Compatibility and upgrade

- Protocol 4 is a breaking upgrade. Update both the Android app and Gateway to 3.0.0; protocol 3 clients and servers cannot connect to the new protocol.
- Install the signed Android APK over the existing app to preserve phone-side pairings. Do not uninstall the app for this upgrade.
- Update the Gateway with `npm install -g pinkcollab@3.0.0`.
- Run `pinkcollab setup` or `pinkcollab service install` to update an existing background service. Changed running services restart and stop active OMP runtimes; stored sessions and pairings remain.
- Event replay is bounded and process-local. Expired replay or a Gateway restart falls back to snapshots and history synchronization.
