PinkCollab v1.2.0: status by default and clearer setup recovery

## Highlights

- Running `pinkcollab` with no command shows host status, or tells you to run `pinkcollab setup` if the host is not configured. It no longer starts a foreground Gateway. Use `pinkcollab serve` for that.
- Repeated setup keeps existing pairings and asks before pairing another phone. Declining or cancelling leaves the Gateway running; pair later with `pinkcollab pair`.
- `pinkcollab doctor` reports the CLI version, the npm launcher version when started through npm, and whether the installed background binary matches the CLI.

## Reliability

- Setup waits at most 120 seconds for Tailscale sign-in and stops status probes if you cancel. Ctrl+C does not abandon an in-flight install or config write.
- If Tailscale is connected but Funnel is not allowed for this device, setup names that policy instead of printing a raw CLI error. Manual HTTPS and Tailscale Serve deployments remain valid.
- Windows service installation explains elevation, wrong-account, cancelled credentials, password-versus-PIN, and logon-right failures. Existing configuration is kept.
- An unchanged background service is not restarted. Binary, config, or service-definition changes still update and restart it.

## Compatibility and upgrade

- Protocol 3, the session/runtime/operation model, WebSocket API, and database schema are unchanged. Install the Android APK and Gateway from this release together.
- Upgrade with `npm install -g pinkcollab@1.2.0`, then run `pinkcollab setup` or `pinkcollab service install`. Changed running services restart, stopping active OMP runtimes; stored sessions and pairings remain.
- Scripts that started a Gateway by running `pinkcollab` or `pinkcollab-gateway` with no subcommand must use `serve`.
- `pinkcollab` and `pinkcollab status` exit nonzero when the managed background service is not running, even if a foreground Gateway is healthy. That does not invalidate externally managed HTTPS, Tailscale Serve, or a custom proxy.
- Windows still uses a same-user service, not a logon task. Installation still needs an administrator terminal as that user, the account password (not a PIN), and the Log on as a service right.
