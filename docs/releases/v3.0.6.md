PinkCollab v3.0.6: external HTTPS setup without Tailscale

## Highlights

- Configure an externally managed HTTPS reverse proxy with `pinkcollab setup --transport external --public-url https://pink.example.com --workspace /srv/projects`.
- External setup reuses background Gateway installation, local health checks, and pairing. It saves the public URL for later pairing without invoking Tailscale.
- Non-interactive external setup requires explicit workspace roots and does not create pairing tokens.

## Fixes

- Switching to external access clears the managed-Funnel diagnostic marker only after configuration changes are saved successfully. Failed saves preserve managed-Funnel diagnostics.
- Windows background integration checks use an isolated Gateway fixture instead of querying machine-wide legacy Windows services. Production legacy-service discovery and ownership checks remain unchanged.

## Upgrade notes

- External HTTPS deployments must repeat `--transport external --public-url <your HTTPS root URL>` when rerunning setup. Omitting the transport still selects Tailscale.
- Configure your reverse proxy to forward WebSocket Upgrade and Authorization headers to the loopback Gateway. Setup checks local Gateway health, not external endpoint reachability, and does not manage DNS or certificates.
- External setup does not remove existing Tailscale mappings. Existing settings, conversations, and phone pairings are preserved.
