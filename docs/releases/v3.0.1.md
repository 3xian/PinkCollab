PinkCollab v3.0.1: Windows login startup without service credentials

## Highlights

- Windows now runs the Gateway under the logged-in desktop user with a hidden login-startup launcher. New installations need no administrator rights, Windows password, or service login permission.
- Closing the terminal or locking the screen leaves the Gateway running. Signing out stops it; log in after a reboot to restore access.
- Updated deployment documentation explains login startup, migration, and upgrade checks.

## Fixes

- Wait for the HTTP listener to be ready before reporting Windows startup or restart success. Port conflicts fail startup instead of appearing successful, and failed updates retain their retry state.
- Stop an existing Windows SCM service through its own backend before migration. Migration and manual stop share the same graceful-stop handling.
- Prevent duplicate background instances and check process creation time before identifying or stopping a recorded PID.
- Use the Android theme color for the message-copy confirmation.

## Compatibility and upgrade

- Protocol 4 is unchanged from 3.0.0. Install the signed Android APK over the existing app to preserve phone-side pairings.
- Update the Gateway with `npm install -g pinkcollab@3.0.1`, then run `pinkcollab setup` or `pinkcollab service install` to update the stable background binary.
- To migrate an old Windows service, run setup once in an Administrator terminal as its original user. The installer verifies the account, binary, and data directory before removing the old service. Later updates use a normal terminal.
- Updates and graceful stops end active OMP runtimes while preserving stored conversations and pairings. Start a stopped installation with `pinkcollab service start`.
- Windows login startup does not automatically restart a crashed Gateway. Use `pinkcollab service start` to recover; if Windows disables the startup entry or Windows Script Host, start it manually after login.
